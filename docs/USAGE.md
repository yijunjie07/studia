# 使用指南

[返回项目首页](../README.md)

## 网页版

执行 `uv run StartWork.py --web`（或 `.venv/bin/python StartWork.py --web`），会在浏览器打开 Studia 的图形界面，和终端版共用同一份登录、模型和答案记忆。

- **切换平台**：侧栏顶部的平台切换器，或 ⌘1 / ⌘2。侧栏只列当前平台的课程，⌘K 可跨平台查找课程和试卷。
- **登录**：智慧树用 App 扫码；MOOC 会在浏览器打开职教云登录页授权。资源库暂时隐藏，请用终端版。
- **课程页**：顶部是学习进度、已完成和待学的单元数、可作答的试卷数。「学习」标签里是自动学习（智慧树共享课还有每日复习，按 `S` 开始第一项），下面的点阵每格是一个学习单元，按章节排列：绿色已完成、斜纹待学、蓝色流动是正在学、红叉失败、空框跳过（作业考试在答题里做）、黄色等你操作，鼠标悬停看名称和时长。「答题」标签里勾选试卷，底部选择「仅生成答案」或「AI 作答并交卷」，交卷需要点两次确认。
- **同时运行**：不同课程可以同时自动学习和 AI 答题，最多 4 个任务。限制只有三条：同一门课不能同时开两个学习类任务（自动学习、每日复习），也不能同时开两个 AI 答题；智慧树同一账号同时只能播放一个视频，所以智慧树的学习类任务一次只跑一个（答题不受影响）。按钮不能点时，下面会写明原因。
- **运行中**：窗口底部的播放条显示一个任务的进度：优先显示当前打开的课程，其余任务点「另有 N 个」去任务页查看。按 `F` 展开专注视图（用时、整门课点阵、可按提醒/错误筛选的日志），有多个任务时顶部可以切换；`⇧S` 停止当前显示的任务，`Esc` 收起。任务在本机后台运行，关掉网页不会中断，关掉终端才会停止。
- **等你操作**：遇到验证码、当日学习时长上限或平台登录过期，任务会停下并标成黄色的「等你操作」，不算失败。「任务」页会给出对应按钮：重新登录、验证后重试，或者等第二天再跑。
- **任务页**：保留最近 20 次记录，点一行看日志。只有失败和等你操作的任务才有处理按钮。
- **设置**：账号（登录 / 退出各平台）、AI 模型（切换、测试、编辑、删除，内置供应商不能删除）、偏好（并发数量、夜读模式）。夜读模式也可以按 `⌘J` / `Ctrl+J` 切换，只记在当前浏览器里。

网页服务只监听本机 `127.0.0.1`，每次启动生成新的访问令牌，只有终端里给出的地址能打开。网页版不支持终端版的手动补答：AI 答不出的题会让该试卷停在未提交，可以改用终端版补答。

### 服务器模式

多人共用一台服务器时使用：账号、邀请码、管理页，每个人的数据分开存放，平台登录和 API Key 加密保存。推荐用 Docker 部署。

#### Docker 部署

```bash
git clone https://github.com/yijunjie07/studia.git && cd studia
STUDIA_PUBLIC_URL=http://服务器IP:8080 docker compose up -d --build
docker compose logs studia        # 找到「设置码」
```

1. 浏览器打开 `STUDIA_PUBLIC_URL` 的地址，第一次进入是「创建管理员」页面：填日志里的设置码、管理员用户名和密码（至少 8 位）。设置码每次启动都会换，管理员创建后失效，用来防止别人抢先占用刚部署好的站点。
2. 之后用管理员登录，在「管理」页生成邀请码发给别人，对方在登录页点「用邀请码注册」。
3. **`STUDIA_PUBLIC_URL` 必须和浏览器地址栏完全一致**（协议、域名或 IP、端口）。不一致时网页会拒绝访问，MOOC 登录跳回来也会失败。可以写在同目录的 `.env` 文件里，不用每次带在命令前面。

可用的环境变量（都写在 `docker-compose.yml` 里，也可以放 `.env`）：

| 变量 | 默认值 | 作用 |
| --- | --- | --- |
| `STUDIA_PUBLIC_URL` | `http://localhost:8080` | 浏览器访问的地址 |
| `STUDIA_MAX_JOBS` | `4` | 全站同时运行的任务数，超出的显示「排队中」 |
| `STUDIA_TRUST_PROXY` | `0` | 放在 Nginx / Caddy 等反向代理后面时设为 `1`，按代理传来的真实 IP 限制登录尝试 |
| `STUDIA_SECRET_KEY` | 空 | 主密钥。不设置时首次启动在数据卷里生成 `secret.key` |

数据都在 Docker 卷 `studia-data`（容器内 `/data`）里：`studia.db` 是账号、邀请码和登录会话的 SQLite 数据库，`users/<用户 ID>/` 是每个人的平台登录、AI 模型、答案记忆和答题报告，`audit.log` 是登录和管理操作记录（不含密码和令牌），`secret.key` 是自动生成的主密钥。

- **主密钥丢了，加密的配置就解不开**，用户需要重新登录平台、重新填 API Key。把 `secret.key` 另外备份一份；更稳妥的做法是用 `python StartWork.py --serve --gen-key` 生成密钥，写进 `.env` 的 `STUDIA_SECRET_KEY`，这样密钥不和数据放在一起。
- 更新：`git pull && docker compose up -d --build`，数据卷保留，登录会话也保留。
- 备份：`docker compose stop`，再备份 `studia-data` 卷。
- 智慧树的接口不接受境外网络访问，服务器要放在国内，或者让 `zhihuishu.com` 走国内线路。
- 对公网开放时请在前面加 HTTPS 反向代理（Caddy、Nginx 等），把 `STUDIA_PUBLIC_URL` 改成 `https://你的域名`，并设置 `STUDIA_TRUST_PROXY=1`。

#### 不用 Docker

```bash
python StartWork.py --serve --data ~/.studia-hosted --port 8080 --public-url http://127.0.0.1:8080
```

首次启动同样会在终端打印设置码，主密钥默认生成在数据目录的 `secret.key`。所有选项见 `python StartWork.py --serve --help`，每个选项都有对应的 `STUDIA_*` 环境变量。也可以不经网页，直接用 `--create-admin 用户名` 在终端创建管理员。

#### 其他

- 每个用户自己最多同时开 4 个任务。
- **答案记忆共享**：MOOC 的标准答案只在同一门课的同一份试卷里共享（见「AI 答题」的答案记忆）。智慧树交卷后平台判定的对错存进 `studia.db`，所有用户共用。一个人答对的题，其他人再遇到时直接用，答错的会避开，不再调用 AI。管理页能看到记了多少题。平台登录、AI 模型和答题报告仍然各人分开。旧版本每人一份的 `zhs-answers.json` 会在启动时并入，原文件改名为 `zhs-answers.json.merged`。
- MOOC 登录会在新标签页打开职教云，完成后跳回 `STUDIA_PUBLIC_URL`。
- 管理员可以停用账号（对方立即被登出）、重置密码、停止任意任务。登录连续失败 5 次会锁定 15 分钟。
- 旧版本存在 `accounts.json` 里的账号会在首次启动时自动导入数据库，原文件改名为 `accounts.json.migrated`。

## 支持范围

| 平台 | 自动学习 | 课程讨论 / 评价 | AI 答题 | 导出题目 |
| --- | --- | --- | --- | --- |
| MOOC / AI 优课（`ai.icve.com.cn`） | ✓ | ✓ | ✓ | ✓ |
| 资源库（`zyk.icve.com.cn`） | ✓ | — | — | — |
| 智慧树（`zhihuishu.com`） | ✓ | — | ✓ | — |

附件作业标为“暂不支持”，不能勾选，全选也会排除，请在平台完成。含音频、图片、附件的题目仍需人工处理。工具不保证答案正确，也不保证完成全部课程要求。

## 自动学习

选择课程后选 **1. 自动学习**，确认摘要后开始。界面同时显示课程进度和本课资源进度：已处理数、总数、百分比，以及成功、跳过、失败统计。读取目录时总数显示 `?`；100% 只表示资源处理完毕，是否成功以结果统计为准。

MOOC / AI 优课在资源处理完成后，还会处理课程活动：

- **主题讨论**：AI 按主题生成回复，最多 20 字。
- **课程评价**：固定五星，评语由 AI 按课程生成。

两者都复用已配置的 AI 模型，开始前会先验证 AI 连接，之后自动提交，无需逐条确认。已参与的讨论、已评价的课程，以及未开始或已截止的讨论都会跳过。读取状态失败、AI 生成失败或写入结果未知时，都不会记为成功，也不会自动重发。资源库只处理学习资源。

## 智慧树

课程列表按 **t** 切换到 **智慧树**。首次使用会在浏览器打开一个二维码页面，用智慧树 App 扫码并在手机上确认，之后自动恢复登录；二维码过期会自动换新。要换账号，在课程列表按 **s** → **退出智慧树登录**。

课程列表同时显示**共享课**和**智慧课程**，选择后进入 **1. 自动学习**：

- **共享课**：逐个播放未完成的视频并上报进度，视频中的弹题按平台给出的正确选项作答。
- **智慧课程**：完成知识点下的文本、课件等资源，视频资源按播放进度上报。

视频是实时播放的（约 1.5 倍速），耗时约为视频时长的三分之二。平台不允许同一账号同时观看多个视频，所以智慧树始终逐个处理，不受并发设置影响。遇到验证码或当日学习时长上限会停止后续课程，请到网页处理后再继续。结束后会回查平台状态，结果页显示已确认完成的视频或资源数量。

**每日复习**：共享课视频看完后，学习习惯分还要求按天规律学习（平台建议每天 25 分钟）。选课后选 **3. 每日复习**，程序从已看完的视频里按日期轮换，1 倍速实时重看 30 分钟后停止；智慧课程会跳过。每天运行一次，习惯分数据次日上午更新。

**AI 答题**：选课后选 **2. AI 答题**。共享课显示章节作业和考试；智慧课程显示各知识点的作业（成绩列是平台的掌握度）和未完成的考试。勾选后在执行摘要里选择"答题并自动交卷"或"仅生成答案"，使用的是课程列表 **s → 模型配置** 里启用的模型。

- 每题都要拿到格式正确的答案才保存；AI 答案格式不对时会重问，最多 3 次。任何一题仍无法作答（AI 失败、题目含音视频、题型不支持）时，整份试卷不交卷，结果页写明第几题和原因。
- 智慧课程作业里的图片会下载后随题目发给模型（只在内存中，不落盘）；图片下载失败、模型仍答不了的单选题，从还没判错的选项里随机选一个。图片存放在阿里云 OSS，使用代理时请把 `aliyuncs.com` 也设为直连。
- 平台判定过的答案会记在本机 `zhs-answers.json`（与设置文件同目录），下次遇到同一道题直接复用、避开判错的答案，填空题会记下交卷后平台公布的标准答案。
- 仓库自带共享答案 `ZHSMain/shared_answers.json`，只含平台确认正确的答案，本机记忆没有的题会先用它，省去 AI 调用；本机判错过的共享答案不会再用。运行 `python -m ZHSMain.memory` 可把本机确认过的答案合并进共享文件。
- 作业交卷后会回查平台判定，显示"答对 x/y 题"；考试只有平台开放答案时才显示答对数。
- 提交请求失败时结果显示"交卷结果未知"，不会自动重发，请到平台核对；AI 服务失败或交卷结果未知会停止剩余试卷。
- 共享课已提交的作业不会自动重做（会消耗平台的重做次数）；考试必须先在网页上手动开考，且有剩余次数、答案未锁定才可选择，程序不会替你开考。不可选的试卷会在列表中注明原因。
- 扫码成功后会初始化共享课考试会话，并随登录状态保存；初始化失败时会提示，进入共享课试卷时重新尝试。
- 共享课试卷请求使用答题页（`onlineexamh5new.zhihuishu.com`）的来源信息；若平台仍要求验证，程序会停止并提示到网页处理。

智慧树的接口不接受境外网络访问。如果使用代理，请把 `zhihuishu.com` 设为直连，否则会提示无法连接。

## AI 答题

**答案记忆**：MOOC 交卷后，平台会在作答记录里公布每道题的标准答案。每次答题前，程序会先读这份试卷所有已交卷记录里的标准答案并记下来，交卷成功后再记一次本轮的；答题时命中记忆的题直接用标准答案，不调用 AI。所以能重做的试卷，重做时通常可以全对。

- 只在**同一门课（同一个班）的同一份试卷**里复用，不同课程、不同试卷之间不共享，哪怕题目文字一样。
- 只记单选、多选、判断题；标准答案和选项上的正确标记必须一致才记。填空、问答题仍由 AI 作答。
- 记忆按选项文字匹配，选项顺序打乱也能对上。读取作答记录失败时只会少记，不影响答题。
- 本机存在配置目录的 `mooc-answers.json`；服务器模式存在 `studia.db`，同一个班的用户之间共享。

每次启动默认进入 MOOC / AI 优课的课程列表，按 **t** 可切换到资源库。选择一门课程，再选 **2. AI 答题**。AI 答题支持常规 MOOC / AI 优课平台，资源库仅提供自动学习。首次需要浏览器登录，之后自动恢复有效的本机登录。任务列表同时显示作业、考试和测验，以及平台完成状态。选定任务后查看执行摘要。

新用户默认使用项目提供的**默认供应商**，无需配置 Key，费用使用项目共享额度。默认供应商固定显示在模型列表顶部，不可修改或删除，界面不显示其接口地址。已有配置的用户保留当前模型，可按回车切换。共享服务可用性取决于供应商和剩余额度；也可选择 **＋ 添加模型** 使用自己的服务。

模型列表用 **↑↓ 选择、回车启用、e 编辑自定义模型、Esc 返回**；实心圆 **●** 表示当前模型，列表显示供应商名称、模型和状态，可填写供应商名称来区分同名模型；旧配置未命名时显示“自定义供应商”。表单只填写供应商名称、接口地址、模型名称和 API Key，用 **Tab / Shift+Tab** 切换字段，再选择 **保存并测试**；Esc 返回上一级并取消编辑，不改动原配置。第一份配置自动启用，新增其他配置不会覆盖或替换当前模型，选中后按回车即可切换。

支持 **OpenAI 兼容的 Chat Completions API 和 Responses API**，保存测试时自动识别并记住可用接口，无需手动选择格式。供应商名称只是显示标签；原生 Gemini、Anthropic 协议仍不支持。旧配置已指定的接口格式继续生效，默认供应商使用预设接口。

- 自定义兼容接口：地址填写 `https://服务商地址/v1`，模型填写服务商提供的 Model ID。程序先测试 Chat Completions，只有服务明确表示接口不支持时才尝试 Responses；HTTP 401、余额不足、超时、普通参数错误和模型不存在不会触发切换。也可填写完整 `/chat/completions` 或 `/responses` 地址，直接指定对应接口。
- DeepSeek：地址填写 `https://api.deepseek.com`，模型填写 `deepseek-chat` 或 `deepseek-reasoner`，Key 使用该服务商的密钥。

编辑自定义模型时原供应商名称、地址和模型已填好，Key 留空保留；换接口地址必须填写新 Key。修改地址、模型或 Key 会在保存测试时重新识别接口；仅改供应商名称保留已识别结果。删除入口位于编辑页，需要确认。删除当前模型后须重新选择一个模型才能答题，程序不会自动换用其他服务。

Key 隐藏输入，和供应商名称、URL、模型及识别结果一起保存到本机用户目录，不回显到终端。内置服务使用项目共享额度，自定义服务由对应账号计费。发送给 AI 的内容只有题干、上下文和选项；不会携带平台 cookies、登录 token、姓名或学号。

任务列表用 **↑↓ 移动、空格勾选／取消、Enter 确认**。顶部 **All** 一次勾选全部可处理任务，再按空格可取消全选；长列表会自动滚动。没有勾选时，回车直接选当前高亮的任务；`/` 搜索、`PageUp` / `PageDown` 翻页。`Esc` 返回，`q` 退出。真实终端的课程列表用 ↑↓ 选择、Enter 进入；仅重定向或脚本输入模式使用编号。

平台的**附件作业**显示“附件作业／暂不支持”，复选框为 `[-]`，不能勾选；全选和保留选择都会排除，编号输入也不能选中。AI 答题与题目导出均暂不处理此类任务，请到平台完成。识别使用任务目录类型，不会为此打开试卷或启动作答。

任务有开放时间时，列表显示**未开始／已截止**，这些任务同样不可勾选，全选与保留选择会排除。方向键移到任务上，底部显示完整起止时间（北京时间）；编号模式在列表下解释不可选原因。按 `r` 刷新可重新读取开放状态。起止时间格式无法识别时显示“时间未知”，需刷新或到平台核对。程序在读取试卷前及交卷前复核时间；排队期间过期的任务会显示“已跳过”，不阻止后续可用任务。

单份试卷被平台拒绝、题目结构不支持、作答时间耗尽或任务被锁定时，会记录该试卷的失败原因并继续下一份。结束后按试卷汇总成功、失败和跳过数量，每份各计一次。平台登录失效、整体限流或服务不可用、AI 服务故障、交卷结果未知及用户暂停仍会停止派发，剩余任务列为“未执行”，不计为失败。连接预检就失败时尚未处理任何试卷，显示失败原因及未执行数量。

任务列表有固定表头，名称、状态、成绩、剩余次数和类型按列对齐；终端窄于 52 列时隐藏类型列，优先保证名称、状态、成绩和剩余次数可读，暂不可选的提示不受影响。状态来自当前账号的平台作答历史：**已提交**表示有确认的交卷记录，**未提交**表示只有草稿，**未作答**表示没有作答记录。查询失败或平台状态无法识别时显示 **?**。按 `r` 可重新读取状态；此查询不会打开试卷或启动作答计时。本地导出文件或 AI 报告不算平台已提交。

成绩和剩余次数只显示数值，单位放在表头：**0** 是真实零分或次数用完，作业没有剩余机会时显示 **x**（平台返回剩余次数 `-1` 或有限次数已用完）；**--** 表示暂无成绩，**待批**表示等待批阅，**不限**表示不限次数，**?** 表示数据未知。剩余次数采用平台额度，实际能否重答仍受开放时间等平台条件约束。

执行摘要显示任务、供应商名称、模型、连接状态和执行方式。默认采用“答题并自动交卷”。回车开始；`m` 打开模型配置，添加、编辑或切换后保留选好的任务和答题设置；`t` 测试当前 AI 连接；`s` 修改执行方式；`Esc` 返回选择任务，并保留上次选择。仅生成本地答案可在当次设置中选择；每次从课程菜单重新进入 AI 答题，执行方式恢复为“答题并自动交卷”。

答题时，上方显示试卷总进度，下方显示本卷已处理题数、百分比及当前阶段（AI 生成、单题重试、交卷、确认结果）。材料题按子题计数；重试不增加已处理题数。只有校验通过、可提交的题目才计入已处理题数。题目进度达到 100% 表示题目已处理完，交卷是否成功以“已交卷”结果为准。

保存配置后自动测试，模型列表分别显示每份配置的上次测试结果。选中任一模型后，按 `t` 或 Tab 切到“测试连接”按钮，原地显示测试中、结果和耗时；不会启用该模型，测试期间可按 Esc 返回。修改地址、模型或 Key 后旧结果失效，仅改供应商名称不清除连接记录。连接失败仍保留已保存的配置，自定义模型可按 e 修正后重新保存测试；执行摘要用简短状态，本机设置显示当前模型上次通过时间或失败原因。测试仅向 AI 服务发送一道固定的连接测试题，不读取课程题目；该请求仍可能产生服务商费用。执行前也会自动测试，失败时不会打开试卷。HTTP 401 会停止后续任务并提示鉴权失败，请核对服务地址和该服务商的 Key。

执行方式：

1. **仅生成答案（不交卷，无成绩）**：答案只保存在本地，不向平台保存或提交，平台不会评分。获取试卷本身可能创建作答记录并开始计时。结果页会显示“答案已生成 · 未交卷”。需要交卷时，在执行摘要按 `s` → 执行方式 → 答题并自动交卷。
2. **AI 答题并自动交卷**：所有题目都支持、答案格式有效时才交卷。模型自报的置信度只是可选的报告元数据，即使缺失或数值异常也不会阻止采用有效答案。

可自动处理纯文本单选、多选、判断、填空、问答，以及由这些类型构成的纯文本子题。图片、音频、附件、未知题型及无法解析的题目仍需在平台处理，程序不会猜测题意，也不会把不支持的题目变成人工补答。

**人工补答**：某道受支持的题目 AI 没给出可用答案（例如返回空答案或格式无效）时，程序先保存其他已完成答案，再在终端显示这道题：题号、题型、AI 未完成原因、材料、题干和全部选项都在屏幕上。直接输入答案后回车：

- 选择题输入选项字母（`B` 是选项 B，不是返回；多选按 `AB` 连写，顺序不限）
- 判断题输入 `y` / `n`
- 填空题按空依次输入，用 `|` 分隔
- 问答题直接输入文字

输入无效时会提示原因并要求重新输入（例如 `Z`、选项重复、空数不符）。`:s`（或 `:q`）保存退出，`Esc` 保存退出，`Ctrl-C` 和终端 EOF 同样是保存退出，都不会交卷。图片、音频、附件等不受支持的题目永远不会进入人工补答，也不会交卷。

补答后整份试卷会询问一次 **“N/N 题已完成，交卷提交整份试卷？”**，列出三个选项：**交卷**（`y`）提交整份试卷；**不交卷**（`n`，默认，直接回车）只保存本地报告并继续下一份（结果页显示“答案已生成 · 未交卷”）；**暂停全部**（`p`）保存本地报告、不交卷，并停止剩余队列。`Esc`、`q`、`Ctrl-C` 或 EOF 等同暂停全部。没有人工补答的纯 AI 试卷不出现这次确认。

**保存与继续**：未交卷的草稿会记录在本地报告里（状态 `待补答` / `未完成`），并标明哪些题是人工答案。下一次对**同一份试卷、同一轮作答**重新执行时，程序先读取当前试卷，把内容、题型、选项、空数、材料上下文都没变的题目答案直接复用（人工答案同样复用），只对改动或缺失的题目重新调用 AI；上一轮仍未完成的问题直接再次提示人工输入，不再调用 AI，然后继续询问交卷确认。换了账号、课程、试卷或新一轮作答（平台任务 ID 变化）不会复用任何旧答案，只会重新生成。报告的 Markdown 摘要分别标注 `AI 答案` 和 `人工答案`。

单题遇到 AI 响应格式异常、连接超时、HTTP 408/429 或服务端 5xx 时，等待 1 秒、2 秒后分别重试，最多重试 2 次。只重试当前题，已完成的答案保留；每次重试前检查作答时间。重试后仍失败的题目记录为“未完成”，只保存本地报告、不交卷，且不会重复请求；鉴权或配置错误直接停止整个队列；交卷请求不自动重发。

重新选择**同一轮作答**的同一份试卷时，内容未变的题目会复用上一轮已通过校验的答案（包括人工答案），只重新生成改动或缺失的题目，上次未完成的问题直接再次提示人工输入而不再调用 AI；换了账号、课程、试卷或平台任务 ID 则全部重新生成。本次运行内的单题重试不影响其他已完成题目；受支持的未完成题目会进入人工补答，不受支持的题目不会。

程序使用真实经过的时间上报作答时长，不伪造考试时长。平台拒绝请求、时间耗尽或计时请求失败时停止处理。再次选择已提交的任务会尝试开始新一轮作答，历史交卷记录不会导致跳过；是否还有次数、是否开放由平台决定。新一轮重新生成答案，上一轮已交卷报告保存在 `ai_results/<课程名>/history/`；同一轮未交卷的草稿会复用未改动题目的已校验答案并继续补答；平台若返回已交卷的同一记录，则停止处理并提示原因。交卷结果未知时先核对平台，不自动重发同一份交卷请求。

## 自动保存与本机设置

课程列表按 **s → 1 模型配置** 打开模型列表，与答题摘要的 **m** 入口相同。按 **2 并发设置** 分别调整 AI 答题和自动学习；还可分别退出 MOOC 与资源库的本机登录，`Esc` 返回课程列表。退出当前平台会立即打开浏览器重新登录；退出另一个平台只清除该平台的本机缓存，下次需要浏览器登录时才先经官方退出地址清除该浏览器共享的 SSO 登录。无论退出哪个平台，另一个平台的本机登录和模型配置都保留。

AI 答题和自动学习分别支持 **1–8 路**执行，默认均为 **8**，沿用已保存的有效设置。并发设置页用 ↑↓ 选项目，←→ 或数字调整；Tab 切换保存、取消、恢复默认，Esc 取消。恢复默认只修改草稿，保存后下次运行生效，取消不改变已保存值。上限 8 是程序允许的并发数，不代表供应商或平台一定允许 8 路；执行摘要只显示执行方式，不显示并发数。

AI 并发发生在同一份试卷内：最多 8 道题同时生成，任一道完成后立即校验、保存并补充下一道，不等整批结束。不同试卷继续依次处理，报告和交卷仍统一进行。自动学习并发发生在当前课程的独立资源之间，课程仍顺序处理，MOOC 与资源库共用同一执行方式。并发不控制导出，也不同时启动“学习”和“答题”两个菜单操作。暂停或 Ctrl+C 后停止派发新任务，已经发出的请求可能仍需等待返回或超时；交卷不会自动重发。

并发答题遇到服务限流或暂时不可用时，在途请求共用冷却时间；429/503 的有效 Retry-After 可延长等待（最多 300 秒），每题仍最多重试 2 次。并发不保证速度更快，遇到限流时程序会遵守服务端的等待要求。学习接口限流或登录失效时停止后续任务，不自动重发学习记录。

首次成功读取账号和课程后保存该平台的访问令牌。下次先向平台验证，再显示课程，不再打开浏览器。服务端明确返回未登录/过期（HTTP 或业务状态码 401）时清除失效缓存，重新登录一次；断网、超时、服务端错误或格式异常会停止本次操作并保留缓存。平台决定令牌有效期，保存不等于永久登录。运行中发生的答题/交卷错误不会通过重新登录自动重放请求。

自动保存的内容包括多份模型配置及各自的测试结果、当前启用的模型、两个平台各自的登录令牌、导出格式与范围，以及答题和学习各自的并发数。旧版本保存的置信度偏好仍保留在配置文件中，但不再影响答题和交卷。平台每次默认 MOOC / AI 优课，执行方式每次默认“答题并自动交卷”，课程和具体任务仍在当次选择。

默认保存位置：macOS / Linux 为 `~/.config/icve-ai-assistant/settings.json`；Windows 为 `%LOCALAPPDATA%\icve-ai-assistant\settings.json`。可通过 `ICVE_CONFIG_DIR` 环境变量指定其他目录。内容是未加密的 JSON，macOS / Linux 新建目录为 `700`、配置文件为 `600`，Windows 使用用户目录继承的访问权限。不要分享或上传该文件。写入采用临时文件加原子替换；保存失败会提示，旧配置不会被覆盖。原文件损坏时停止并提示路径，不会静默覆盖。

旧版已保存的单份 AI 配置会自动作为当前模型显示，首次修改模型列表时原子迁移，无需重新输入 Key。在设置里退出登录会同时清除本机缓存和默认浏览器里的 SSO 登录（另一个平台的本机缓存保留）；清缓存失败时保留原登录状态，不触发浏览器退出；清缓存成功后，若重新登录超时或取消，同一程序会话中的退出标记会保留到下次登录。

## 本地结果与恢复

- 题目导出：`tiku/<课程名>/`，可输出 `.md`、`.docx`；`-dev` 模式额外输出 JSON 和原始数据。
- AI 报告：`ai_results/<课程名>/<任务标识>.json` 与同名 `.md`，包含 AI 答案、依据、校验结果和执行状态。
- `preview`：仅生成本地答案。
- `needs_review`：存在未完成的题目，未交卷。
- `ai_error`：AI 服务失败，停止后续题目和任务，未交卷。
- `submitted`：交卷后已查询平台记录并确认状态。
- `submission_unknown` / `submitting`：请求可能已发出，但结果未确认；先在网页核对，程序不会自动重发。
- `error`：本份试卷失败，保留错误原因并继续下一份；若标记 `stop_queue=true`，表示平台服务故障，停止队列。

同一账号的同一课程任务使用独立文件锁，避免两个进程重复处理。正常退出会删除 `.lock`；若进程被强制关闭，确认没有其他实例运行、核对网页状态后才可清理该任务的 `.lock`。不要为重试未知结果而直接删除交卷报告。

报告、日志、虚拟环境和本机密钥配置文件均由 .gitignore 排除。内置共享 Key 由项目维护者授权随客户端分发，可从客户端提取；维护者应在供应商端限制额度及模型权限。个人 Key 和平台登录令牌不要加入源码。开启 `-dev` 后的导出原始数据可能包含个人信息，请不要公开上传。

## 题目导出与答案来源

进入课程后选择 **3. 导出题目**，在任务列表中选择作业、考试或测验，再查看执行摘要。格式、文件组织、是否包含“我的答案”沿用上次设置；回车直接开始，`s` 按需修改。

选择范围和文件组织彼此独立：可以只选几份任务，然后选“每份一个文件”或“按课程合并”。合并仅包含当前课程中所选的任务。支持 Markdown、Word 或两种格式同时导出；不同类别的所选题目也可以合并。

- **答案**：来自平台返回的标准答案或答题记录中的答案字段，未逐题验证正确性。
- **我的答案**：当前账号已有的作答记录；选择包含此项只会导出记录，不会开始答题或交卷。
- 平台未返回答案时，文件会标注“平台未返回”，导出功能不会调用 AI 补答。

文件保存到 `tiku/<课程名>/`。AI 模式生成的答案另存到 `ai_results/`，与平台导出的答案来源不同。

## 终端操作与结果

启动后默认显示 MOOC / AI 优课的课程：`↑↓` 移动高亮，`Enter` 进入当前课程，`/关键词` 搜索，`PageUp` / `PageDown` 翻页；`s` 设置、`t` 切换平台、`r` 刷新课程。进入课程后执行操作，完成后在结果页按 `Enter` 或 `1` 返回本课程，按 `2` 直接切换课程，无需重启。

真实终端里所有页面共用同一套键盘操作：`↑↓`（选择器里也支持 `←→`）移动，`Enter` 采用当前高亮项或确认，`Tab` / `Shift+Tab` 在列表与按钮之间移动焦点，`Esc` 返回上一级，`q` 退出。课程首页没有上一级时 `Esc` 留在首页；`PageUp` / `PageDown` 翻页。任务使用空格勾选，无需输入编号范围或分类命令。返回任务列表后，上次选择仍保持勾选，回车即可确认；`r` 刷新状态也会保留勾选。模型表单按 Esc 放弃未保存修改，模型表单中的 q 作为普通文本；运行中的任务仍用 Ctrl+C 停止。当前真正绑定按键的页面：结果页 `1` 返回本课程、`2` 切换课程（与按钮一致）；模型列表 `t` 测试、`e` 编辑；任务列表 `r` 刷新状态。菜单里标出的编号按下即选中。页面上没有标出的按键不会触发任何操作，也没有 `b` 返回。

重定向标准输入或由脚本调用时，使用兼容的编号输入模式；仅此模式保留 `1,3`、`1-3`、`all`、搜索和类别筛选。

运行时顶部显示任务名、进度条、已完成/总数与用时，下方显示最多 8 行日志，小窗口自动缩减日志区域，长行截断。页面切换在原位置更新，Esc 返回保留选择；运行时回车不回显、不增加空行，也不会带入下一次确认。Ctrl+C 仍可停止。读取未知数量的目录时显示 `?`；导出总数随目录读取逐步增加。交互式终端自动刷新，重定向到文件时不写入动态刷新内容。

自动学习另有“本课资源”进度条：目录读取时显示 `0/?`，去重统计后显示已处理数／总数和百分比，每个资源处理结束就更新。下方显示资源名称及成功、跳过、失败数；已学完或不支持的资源计为跳过，处理失败也计入已处理，取消前未完成的资源不计入。100% 不表示全部学习成功，课程结果仍以成功、跳过、失败统计为准。

结束或 Ctrl+C 中断后清除动态区域，保留结果页：各任务状态、成功/失败数、执行用时、输出文件位置和需要处理的错误。学习管理按课程计数（至少处理一个资源且无捕获错误才算成功，不表示已满足全部课程要求）；导出按写完文件的试卷计数；AI 按试卷计数，本地报告生成与已确认交卷算成功。未完成和交卷结果未知计入失败并单独标注。读取目录等前置错误也会计入失败；未开始的任务不算完成。每次操作单独统计，选择课程与修改设置的时间不计入任务执行用时。

完整业务日志保存在运行目录下的日期 `.log` 文件中。动态面板消失后，可结合日志和本地报告查看详情。`-dev` 会让面板包含调试消息。

无需账号的界面预览：`python -m tools.ui_demo`。该预览只使用模拟数据，不访问平台或 AI。在真实终端可用 `python -m tools.ui_demo --native` 预览原生键盘控件：菜单、课程单选、确认、多选、模型/并发以及执行摘要/结果页，同样只使用合成数据，不写入配置。
